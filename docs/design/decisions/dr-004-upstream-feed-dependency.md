# DR-004: 上流フィード依存の緩和（feeder 版自走条項）

> 種別: 設計不変条件 ／ 状態: 有効 ／ 決定日: 2026-07-24 ／ 決定者: DRI ／ 参照: saita-kun-planner dr-004（上流非依存で自走）

## 決定

feeder は本質的に**フィード消費者**であり、planner の「入口 B（公式公募要領からの spec 自作）」に相当する完全自走経路は存在しない。この事実を隠さず、継続性は次の 3 点で構造的に担保する。

1. **producer の代替可能性**: 公開データ契約（`feed-contract-v1.md` + 機械可読 schema + 準拠チェッカ `tools/check-feed-contract.sh`）を repo に同梱して公開する。サイタくん本体が停止しても、契約準拠の JSON を吐ける者がいればハーネスは無改造で動く。`feed_base_url` はプロファイルで設定可能であり、中央 URL のハードコード必須化は設計違反。
2. **劣化継続**: 直近正常取得のローカルキャッシュ（`state/cache/`）により、フィード取得失敗・検証失敗時も新着が増えないだけで、状態・履歴・再実行は壊れない。
3. **鮮度の可視化**: フィードの鮮度劣化（48h 超）はダイジェストのバナーで必ず surface する。静かに古い情報を配り続けない。

## 保証しないこと（正直に記録する）

フィードが停止し、代替 producer も現れなければ、新着配信は止まる。これは feeder の構造的限界である。ただし「メンテナ不在時は利用を停止してください」という運用前提は書かない（planner dr-004 の違反例に該当）。継続性の保険は人の引き継ぎではなく、**契約の公開性と producer の代替可能性**という構造である。

## 制約（運用 AI が守ること）

- 実行時にサイタくん本体の API・アカウント登録・認証を要求する変更をしない。フィード取得は認証なしの静的ファイル GET のみ。
- 契約文書・schema・準拠チェッカをコア層から外さない（これらが producer 代替可能性の実体）。
- 鮮度警告・キャッシュフォールバックを「うるさいから」と無効化しない。

## 違反例

- フィード取得に API キーを導入する。
- meta.json の取得先を定数に固定し、profile の `feed_base_url` を無視する実装。
