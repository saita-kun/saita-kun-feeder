# DR-001: 入力は公開データ契約経由のみ（DB 直結・スクレイプ・LLM 抽出の非同梱）

> 種別: 設計不変条件 ／ 状態: 有効 ／ 決定日: 2026-07-24 ／ 決定者: DRI

## 決定

本ハーネスの補助金データ入力は、`docs/design/feed-contract-v1.md` に準拠した公開データフィード（CDN 静的ファイル）**のみ**とする。データベースへの直接アクセス（Supabase REST / SQL）、Web スクレイピング、LLM による情報抽出は、本ハーネスに組み込まない。

## 理由

- 入力を「判定可能な単一の契約面」に絞ることが、品質保証（sha256 検証・スキーマ検証・golden E2E）を成立させる唯一の構造。入力経路が増えるほど、検証できない挙動が増える。
- スクレイピング・抽出は取り込み側（producer）の責務であり、そこには鮮度検査・重複排除・分類の大きな品質基盤が必要。ハーネス側に半端に持ち込むと、その品質基盤なしで劣化コピーが動くことになる。
- 静的ファイルの GET だけなら、利用者側に API キー・認証・レート制限の考慮が一切不要で、fork がどれだけ増えても producer 側の負荷設計が壊れない。

## 制約（運用 AI が守ること）

- フィード取得以外のネットワーク読み取りを runner・lib に追加しない。
- 「フィードにない補助金も拾いたい」という要望には、producer 側（サイタくん本体）への情報源追加要望として案内する。ハーネス側での取得実装は設計違反。
- 契約の変更（フィールド追加・sentinel 変更）は `feed-contract-v1.md` の改訂として行い、consumer 実装だけを先行させない。

## 違反例

- `lib/` に HTML パーサや LLM 呼び出しを追加して「フィード補完」を行う。
- Supabase の anon キーを README に書いて REST 直叩きの手順を案内する。
