# データ憲章（参照）

サイタくんプロジェクトのデータガバナンスの正本は、姉妹 repo saita-kun-planner の
[`docs/governance/data-charter.md`](https://github.com/saita-kun/saita-kun-planner/blob/main/docs/governance/data-charter.md) です。feeder はその派生プロジェクトとして次の条項に従います。

## feeder に直接関わる条項（自己完結のための転記）

- **生フィードの無料公開**（憲章 §8）: 構造化した補助金フィード（レジストリ）は無料公開し、OSS 利用者が検証できる形で維持する。feeder が消費する公開データフィード（`docs/design/feed-contract-v1.md`）はこの条項の実装である。
- **集計データの外部配布ライセンス = CDLA-Permissive-2.0**（憲章 §6 関連）: feeder のフィードも同ライセンスで統一する。
- **採否データの row-level 公開禁止**（憲章 §6）: 採否（result）データは feeder のスコープに一切含めない。feeder は採否データを収集も配信もしない。
- **スポンサー独立**（憲章 §7）: フィードの掲載・順序は資金提供の影響を受けない。feeder 側の基準順序は登録業種との具体一致 → 締切昇順 → 金額降順 → id。共有予算で選択に成功した行の先頭 5 件に、締切が基準日から 14 日以内（UTC 日付基準）の urgent 行を 2 枠確保する。予算を通らない行は枠を埋めず、配信可能な urgent 行から不足分だけ繰り上げる。該当行が足りなければある分だけ採用し、残りは基準順序を維持する。先頭 5 件以降も、繰り上げ済み・予算除外の行を除いた基準順序に従う。資金提供による優先表示の仕組みは持たない。

業種・urgent 順序の補足（`lib/select.js`）:

- **業種不問行の暫定判定**: `category_other` を除く 11 個の業種フラグのうち、8 個以上が 1 の行。広範な業種にフラグが立つ行を具体的な業種一致として優先しないための閾値であり、一部フラグが欠けた広範な行も扱えるよう全 11 個一致を要求しない。フィードの分類自体は変更しない。
- **基準日の扱い**: `opts.today` が未指定・不正なら urgent 枠確保を行わず、壁時計を参照しない。業種が空・未指定なら締切 → 金額 → id の順序。数値予算の API は従来どおり、urgent 枠を確保した並び順を指定件数で切る。
- **撤去条件**: feed contract v2（[issue #16](https://github.com/saita-kun/saita-kun-feeder/issues/16)）で producer 側に業種不問の専用表現が入り次第、暫定的な業種一致キーを撤去する。

## feeder 固有の追加原則

- テレメトリなし・収集なし（TERMS 第 3 条）。データは一方向（producer → 利用者）にのみ流れる。
